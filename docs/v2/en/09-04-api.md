# The public API

SwiftyEdit provides a REST API that lets other applications read your content - for example a
second website, an app or a price comparison feed. The API is meant to be called __server-side__
(e.g. from PHP); the API key belongs on the server, never into JavaScript running in a browser.

* Base URL: `https://example.com/api/v1/`
* All responses are JSON (`Content-Type: application/json`).
* The version is part of the URL. A future, incompatible version gets a new path (`/api/v2/`),
  so existing integrations keep working.
* API requests don't start a session and don't set cookies.

API keys are created in the backend under
[Settings ▶ API keys](08-00-settings.md#api-keys).

## Authentication

Every request needs an API key in the `Authorization` header:

```
Authorization: Bearer se_1234567890abcdef...
```

The key is __not__ accepted as a query parameter, as it would end up in server logs and the
browser history otherwise.

{alert:warning}
__Server configuration:__ With Apache and PHP-FPM/CGI, the `Authorization` header is not passed
on to PHP by default. SwiftyEdit's `.htaccess` takes care of this. If you use your own server
configuration, make sure the header reaches PHP - otherwise every request is answered with
`401 Missing API key`.
{/alert}

## Permissions (scopes)

Each key only gets the permissions selected when it was created:

| Scope             | Allows                                                                                       |
|-------------------|----------------------------------------------------------------------------------------------|
| `products:read`   | Read products (`GET /api/v1/products/`).                                                     |
| `products:prices` | Additionally get prices if the shop only shows them to logged-in customers. Requires `products:read`. |
| `posts:read`      | Read blog posts (`GET /api/v1/posts/`).                                                      |
| `events:read`     | Read events (`GET /api/v1/events/`).                                                         |
| `pages:read`      | Read pages (`GET /api/v1/pages/`).                                                           |

The required scope follows from the resource and the HTTP method: `GET` and `HEAD` need
`{resource}:read`, all other methods `{resource}:write`. A method that a resource doesn't
support is answered with `405`.

## Errors

Errors are returned with a matching HTTP status code and always have the same format:

```json
{"error": {"status": 401, "message": "Invalid or revoked API key"}}
```

| Status | Meaning                                                                          |
|--------|----------------------------------------------------------------------------------|
| `400`  | Invalid parameter, e.g. a malformed `lang`.                                      |
| `401`  | No API key sent, or the key is unknown or revoked.                               |
| `403`  | The key doesn't have the required scope.                                         |
| `404`  | Unknown API version, unknown resource, or the record doesn't exist (or isn't public). |
| `405`  | The resource doesn't support this HTTP method.                                   |

## Products

### List

```
GET /api/v1/products/
```

Returns the public products, without variants, in the same order as the shop listing.

| Parameter  | Default | Description                                                    |
|------------|---------|----------------------------------------------------------------|
| `lang`     | –       | Only products in this language, e.g. `de`. Without it, all languages. |
| `page`     | `1`     | Page number.                                                   |
| `per_page` | `20`    | Products per page, max. `100`.                                 |
| `render`   | –       | `1` resolves snippets and shortcodes in `teaser` and `text`, see below. |

The response contains the products in `data` and the pagination in `meta`:

```json
{
  "data": [ { "id": 23, "title": "Flyer DIN A4", ... } ],
  "meta": { "page": 1, "per_page": 20, "total": 10, "total_pages": 1 }
}
```

### Single product

```
GET /api/v1/products/{id}/
```

Returns a product or a single variant. A product additionally contains its variants in
`variants`. The `render` parameter works here as well.

### Visibility

The API follows the same rules as the frontend:

* Drafts and products with a release date in the future are never returned (`404`).
* Products with the status "invisible" don't appear in the list, but can be fetched by their
  id - like a direct link in the frontend.

### Fields

| Field              | Description                                                                         |
|--------------------|-------------------------------------------------------------------------------------|
| `id`, `uuid`       | Id and UUID of the record.                                                          |
| `type`             | `product` or `variant`.                                                             |
| `parent_id`        | For variants the id of the main product, otherwise `null`.                          |
| `lang`             | Language of the product.                                                            |
| `title`, `variant_title` | Title and variant title as plain text.                                        |
| `teaser`, `text`   | HTML. Snippets and shortcodes are only resolved with `render=1`.                    |
| `slug`, `url`      | Slug and full canonical URL of the product page.                                    |
| `images`           | List of absolute image URLs.                                                        |
| `categories`       | List of categories with `name` and `slug`.                                          |
| `tags`             | List of tags with `name` and `slug`.                                                |
| `product_number`, `manufacturer`, `ean`, `mpn` | Product data.                                           |
| `price`            | `net`, `gross`, `tax_rate` and `currency` - or `null`, see below.                   |
| `unit`, `unit_content` | Unit and content, e.g. for base prices.                                         |
| `meta_title`, `meta_description`, `meta_keywords` | Meta data.                                         |
| `released_at`, `updated_at` | Unix timestamps.                                                           |

Text fields are returned decoded - escape them yourself when you output them as HTML.

### Prices

`price` is `null` if

* the price is hidden for this product, or
* the shop only shows prices to logged-in customers and the key doesn't have the
  `products:prices` scope.

Price groups and tax classes are resolved the same way as in the shop. Variants are returned with
their own price; there is no "from" price across all variants.

### Snippets and shortcodes

By default, `teaser` and `text` are returned as stored, so shortcodes like `[snippet=name]` stay
in the text. With `render=1` they are resolved - in the language of the product, with the same
placeholders as on the product page. `[script]`, `[plugin]` and `[include]` are never executed.
See [Snippets in the API](03-00-snippets.md#api).

## Blog posts

### List

```
GET /api/v1/posts/
```

Returns the public blog posts in the same order as the blog listing: pinned posts first, then the
newest.

| Parameter  | Default | Description                                                                   |
|------------|---------|-------------------------------------------------------------------------------|
| `lang`     | –       | Only posts in this language, e.g. `de`. Without it, all languages.            |
| `type`     | –       | Only these types, comma separated: `message`, `image`, `gallery`, `video`, `link`, `file`. |
| `category` | –       | Only posts in this category (its slug, e.g. `news`).                          |
| `page`     | `1`     | Page number.                                                                  |
| `per_page` | `20`    | Posts per page, max. `100`.                                                   |
| `render`   | –       | `1` resolves snippets and shortcodes in `teaser` and `text`, like for products. |

The response has the same structure as the product list (`data` and `meta`).

### Single post

```
GET /api/v1/posts/{id}/
```

Drafts and posts with a release date in the future are never returned (`404`).

### Fields

| Field              | Description                                                                         |
|--------------------|-------------------------------------------------------------------------------------|
| `id`, `uuid`       | Id and UUID of the post.                                                            |
| `type`             | `message`, `image`, `gallery`, `video`, `link` or `file`.                           |
| `lang`             | Language of the post.                                                               |
| `title`            | Title as plain text.                                                                |
| `teaser`, `text`   | HTML. Snippets and shortcodes are only resolved with `render=1`.                    |
| `slug`, `url`      | Slug and full URL of the detail page. `url` is `null` if the post has no detail page. |
| `images`           | List of absolute image URLs.                                                        |
| `gallery`          | For galleries the absolute URLs of all gallery images, otherwise an empty list.     |
| `video_url`        | For videos the video URL, otherwise `null`.                                         |
| `link`             | `url` and `text` of the link, or `null`.                                            |
| `file`             | `url`, `external_url`, `license` and `version` of the file, or `null`.              |
| `categories`, `tags` | Lists with `name` and `slug`.                                                     |
| `author`, `source` | Author and source.                                                                  |
| `meta_title`, `meta_description`, `meta_keywords` | Meta data.                                         |
| `released_at`, `updated_at` | Unix timestamps.                                                           |

## Events

### List

```
GET /api/v1/events/
```

Like the frontend, the list returns __upcoming__ events by default, ordered by start date.
An event counts as past once its end date is older than the time offset set under
[Settings ▶ Events](08-00-settings.md).

| Parameter  | Default    | Description                                                                 |
|------------|------------|-----------------------------------------------------------------------------|
| `period`   | `upcoming` | `upcoming`, `past` (newest first) or `all`.                                 |
| `lang`     | –          | Only events in this language, e.g. `de`. Without it, all languages.         |
| `category` | –          | Only events in this category (its slug).                                    |
| `page`     | `1`        | Page number.                                                                |
| `per_page` | `20`       | Events per page, max. `100`.                                                |
| `render`   | –          | `1` resolves snippets and shortcodes in `teaser` and `text`, like for products. |

The response has the same structure as the product list (`data` and `meta`).

### Single event

```
GET /api/v1/events/{id}/
```

Also returns past events. Drafts and events with a release date in the future are never returned
(`404`).

### Fields

| Field              | Description                                                                         |
|--------------------|-------------------------------------------------------------------------------------|
| `id`, `uuid`       | Id and UUID of the event.                                                           |
| `lang`             | Language of the event.                                                              |
| `title`            | Title as plain text.                                                                |
| `teaser`, `text`   | HTML. Snippets and shortcodes are only resolved with `render=1`.                    |
| `slug`, `url`      | Slug and full URL of the event page.                                                |
| `start_at`, `end_at` | Start and end as Unix timestamps.                                                 |
| `location`         | `street`, `street_nbr`, `zip` and `city`.                                           |
| `price_note`       | Price information as HTML.                                                          |
| `guestlist`        | `null` if there is no guest list. Otherwise `access` (`registered` or `everybody`), `limit` (or `null` for no limit) and `confirmed` - the number of confirmations, or `null` if it isn't shown publicly. |
| `images`           | List of absolute image URLs.                                                        |
| `categories`, `tags` | Lists with `name` and `slug`.                                                     |
| `author`           | Author.                                                                             |
| `meta_title`, `meta_description`, `meta_keywords` | Meta data.                                         |
| `released_at`, `updated_at` | Unix timestamps.                                                           |

## Pages

### List

```
GET /api/v1/pages/
```

Returns the public pages, sorted by their position in the page tree. With `parent` you can
build the navigation level by level.

| Parameter  | Default | Description                                                                  |
|------------|---------|------------------------------------------------------------------------------|
| `lang`     | –       | Only pages in this language, e.g. `de`. Without it, all languages.           |
| `parent`   | –       | Only the children of this page id, or `none` for pages without a parent (home pages and single pages). |
| `type`     | –       | Only pages with this type of use, e.g. `imprint` or `privacy_policy`.        |
| `page`     | `1`     | Page number.                                                                 |
| `per_page` | `20`    | Pages per page, max. `100`.                                                  |
| `render`   | –       | `1` resolves snippets and shortcodes in `content`, like for products.        |

### Single page

```
GET /api/v1/pages/{id}/
```

### Visibility

* The list only contains pages with the status "public". Pages with the status "invisible"
  can be fetched by their id - like a direct link in the frontend.
* Drafts, private pages, password protected pages and pages restricted to user groups are never
  returned (`404`). An API key is not a logged-in user.

### Fields

| Field              | Description                                                                         |
|--------------------|-------------------------------------------------------------------------------------|
| `id`               | Id of the page.                                                                     |
| `lang`             | Language of the page.                                                               |
| `title`, `linkname` | Title and link name (the label in the navigation) as plain text.                   |
| `content`          | HTML. Snippets and shortcodes are only resolved with `render=1`. Content generated by a plugin is not included. |
| `slug`, `url`      | Permalink and full URL of the page.                                                 |
| `parent_id`, `position` | Position in the page tree: parent page (or `null`) and sort order among siblings. |
| `is_home`          | `true` for the home page of the language.                                           |
| `in_navigation`    | Whether the page appears in the navigation.                                         |
| `type`             | Type of use, e.g. `normal`, `search`, `imprint`.                                    |
| `module`           | Name of the plugin that is embedded in the page, or `null`.                         |
| `redirect`         | `url` and `code` if the page redirects, otherwise `null`.                           |
| `target`           | Link target, e.g. `_self`, or `null`.                                               |
| `translations`     | The page in other languages, as an object `{"en": "https://..."}`.                  |
| `images`           | List of absolute image URLs (page thumbnail).                                       |
| `tags`             | List of tags with `name` and `slug`.                                                |
| `meta_description`, `meta_keywords`, `meta_robots`, `meta_author` | Meta data.                         |
| `updated_at`       | Unix timestamp.                                                                     |

## Example: calling the API from PHP

```php
<?php
$api_key = 'se_...'; // e.g. from a config file outside the web root

$ch = curl_init('https://example.com/api/v1/products/?lang=en&per_page=10');
curl_setopt_array($ch, [
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => ['Authorization: Bearer ' . $api_key],
    CURLOPT_TIMEOUT => 10,
]);
$response = curl_exec($ch);
$status = curl_getinfo($ch, CURLINFO_HTTP_CODE);
curl_close($ch);

if ($response === false) {
    die('API not reachable');
}

$json = json_decode($response, true);

if ($status !== 200) {
    die('API error ' . $status . ': ' . ($json['error']['message'] ?? 'unknown'));
}

foreach ($json['data'] as $product) {
    echo htmlspecialchars($product['title']) . '<br>';
}
```
