# Die öffentliche API

SwiftyEdit stellt eine REST-API bereit, über die andere Anwendungen Deine Inhalte lesen können -
zum Beispiel eine zweite Website, eine App oder ein Preisvergleichs-Feed. Die API ist für den
Aufruf __auf dem Server__ gedacht (z.B. aus PHP); der API-Key gehört auf den Server und niemals
in JavaScript, das im Browser läuft.

* Basis-URL: `https://example.com/api/v1/`
* Alle Antworten sind JSON (`Content-Type: application/json`).
* Die Version ist Teil der URL. Eine spätere, inkompatible Version bekommt einen neuen Pfad
  (`/api/v2/`), bestehende Anbindungen funktionieren also weiter.
* API-Anfragen starten keine Session und setzen keine Cookies.

API-Keys legst Du im Backend unter
[Einstellungen ▶ API-Keys](08-00-settings.md#api-keys) an.

## Authentifizierung

Jede Anfrage braucht einen API-Key im `Authorization`-Header:

```
Authorization: Bearer se_1234567890abcdef...
```

Als Query-Parameter wird der Key __nicht__ akzeptiert, da er sonst in Server-Logs und im
Browserverlauf landen würde.

{alert:warning}
__Server-Konfiguration:__ Mit Apache und PHP-FPM/CGI wird der `Authorization`-Header
standardmäßig nicht an PHP weitergegeben. Die `.htaccess` von SwiftyEdit kümmert sich darum.
Nutzt Du eine eigene Server-Konfiguration, stelle sicher, dass der Header bei PHP ankommt -
sonst wird jede Anfrage mit `401 Missing API key` beantwortet.
{/alert}

## Berechtigungen (Scopes)

Jeder Key bekommt nur die Berechtigungen, die beim Anlegen ausgewählt wurden:

| Scope             | Erlaubt                                                                                          |
|-------------------|--------------------------------------------------------------------------------------------------|
| `products:read`   | Produkte lesen (`GET /api/v1/products/`).                                                        |
| `products:prices` | Zusätzlich Preise erhalten, wenn der Shop sie nur angemeldeten Kunden zeigt. Setzt `products:read` voraus. |

Die nötige Berechtigung ergibt sich aus Ressource und HTTP-Methode: `GET` und `HEAD` brauchen
`{ressource}:read`, alle anderen Methoden `{ressource}:write`. Eine Methode, die eine Ressource
nicht unterstützt, wird mit `405` beantwortet.

## Fehler

Fehler kommen mit dem passenden HTTP-Statuscode und haben immer dasselbe Format:

```json
{"error": {"status": 401, "message": "Invalid or revoked API key"}}
```

| Status | Bedeutung                                                                                   |
|--------|---------------------------------------------------------------------------------------------|
| `400`  | Ungültiger Parameter, z.B. ein fehlerhaftes `lang`.                                         |
| `401`  | Kein API-Key gesendet, oder der Key ist unbekannt bzw. gesperrt.                            |
| `403`  | Dem Key fehlt die nötige Berechtigung.                                                      |
| `404`  | Unbekannte API-Version, unbekannte Ressource, oder der Datensatz existiert nicht (bzw. ist nicht öffentlich). |
| `405`  | Die Ressource unterstützt diese HTTP-Methode nicht.                                         |

## Produkte

### Liste

```
GET /api/v1/products/
```

Liefert die öffentlichen Produkte ohne Varianten, in derselben Reihenfolge wie die Shop-Liste.

| Parameter  | Standard | Beschreibung                                                          |
|------------|----------|-----------------------------------------------------------------------|
| `lang`     | –        | Nur Produkte in dieser Sprache, z.B. `de`. Ohne Angabe alle Sprachen. |
| `page`     | `1`      | Seitennummer.                                                         |
| `per_page` | `20`     | Produkte pro Seite, höchstens `100`.                                  |
| `render`   | –        | `1` löst Snippets und Shortcodes in `teaser` und `text` auf, siehe unten. |

Die Antwort enthält die Produkte in `data` und die Seitenaufteilung in `meta`:

```json
{
  "data": [ { "id": 23, "title": "Flyer DIN A4", ... } ],
  "meta": { "page": 1, "per_page": 20, "total": 10, "total_pages": 1 }
}
```

### Einzelnes Produkt

```
GET /api/v1/products/{id}/
```

Liefert ein Produkt oder eine einzelne Variante. Ein Produkt enthält zusätzlich seine Varianten
in `variants`. Der Parameter `render` funktioniert auch hier.

### Sichtbarkeit

Die API folgt denselben Regeln wie das Frontend:

* Entwürfe und Produkte mit einem Veröffentlichungsdatum in der Zukunft werden nie ausgeliefert
  (`404`).
* Produkte mit dem Status „Unsichtbar“ erscheinen nicht in der Liste, lassen sich aber über ihre
  ID abrufen - wie ein Direktlink im Frontend.

### Felder

| Feld               | Beschreibung                                                                         |
|--------------------|--------------------------------------------------------------------------------------|
| `id`, `uuid`       | ID und UUID des Datensatzes.                                                         |
| `type`             | `product` oder `variant`.                                                            |
| `parent_id`        | Bei Varianten die ID des Hauptprodukts, sonst `null`.                                |
| `lang`             | Sprache des Produkts.                                                                |
| `title`, `variant_title` | Titel und Variantentitel als reiner Text.                                      |
| `teaser`, `text`   | HTML. Snippets und Shortcodes werden nur mit `render=1` aufgelöst.                   |
| `slug`, `url`      | Slug und vollständige Canonical-URL der Produktseite.                                |
| `images`           | Liste der absoluten Bild-URLs.                                                       |
| `categories`       | Liste der Kategorien mit `name` und `slug`.                                          |
| `tags`             | Liste der Tags mit `name` und `slug`.                                                |
| `product_number`, `manufacturer`, `ean`, `mpn` | Produktdaten.                                            |
| `price`            | `net`, `gross`, `tax_rate` und `currency` - oder `null`, siehe unten.                |
| `unit`, `unit_content` | Einheit und Inhalt, z.B. für Grundpreise.                                        |
| `meta_title`, `meta_description`, `meta_keywords` | Metadaten.                                          |
| `released_at`, `updated_at` | Unix-Zeitstempel.                                                           |

Textfelder kommen dekodiert an - escape sie selbst, wenn Du sie als HTML ausgibst.

### Preise

`price` ist `null`, wenn

* der Preis bei diesem Produkt ausgeblendet ist, oder
* der Shop Preise nur angemeldeten Kunden zeigt und der Key die Berechtigung `products:prices`
  nicht hat.

Preisgruppen und Steuerklassen werden aufgelöst wie im Shop. Varianten kommen mit ihrem eigenen
Preis; einen „ab“-Preis über alle Varianten gibt es nicht.

### Snippets und Shortcodes

Standardmäßig kommen `teaser` und `text` so, wie sie gespeichert sind - Shortcodes wie
`[snippet=name]` bleiben also im Text stehen. Mit `render=1` werden sie aufgelöst, und zwar in der
Sprache des Produkts und mit denselben Platzhaltern wie auf der Produktseite. `[script]`,
`[plugin]` und `[include]` werden nie ausgeführt. Siehe
[Snippets in der API](03-00-snippets.md#api).

## Beispiel: Die API aus PHP aufrufen

```php
<?php
$api_key = 'se_...'; // e.g. from a config file outside the web root

$ch = curl_init('https://example.com/api/v1/products/?lang=de&per_page=10');
curl_setopt_array($ch, [
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => ['Authorization: Bearer ' . $api_key],
    CURLOPT_TIMEOUT => 10,
]);
$response = curl_exec($ch);
$status = curl_getinfo($ch, CURLINFO_HTTP_CODE);
curl_close($ch);

if ($response === false) {
    die('API not reachable');
}

$json = json_decode($response, true);

if ($status !== 200) {
    die('API error ' . $status . ': ' . ($json['error']['message'] ?? 'unknown'));
}

foreach ($json['data'] as $product) {
    echo htmlspecialchars($product['title']) . '<br>';
}
```
