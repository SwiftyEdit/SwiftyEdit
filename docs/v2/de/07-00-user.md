# Benutzerverwaltung

<kbd>Backend</kbd> ▶ <kbd>Benutzer</kbd>

Es gibt zwei Möglichkeiten, Benutzerkonten zu erstellen.
Über das Frontend können sich Nutzer selbstständig registrieren
(sofern diese Funktion in den Einstellungen aktiviert ist), oder das Benutzerkonto wird über das Backend erstellt.

Wenn sich ein Benutzer über das Frontend registriert,
muss er sein Konto bestätigen. D.h. er muss auf den **Bestätigungslink** klicken,
der automatisch an seine E-Mail-Adresse gesendet wird.

## Die (Benutzer-)Rechteverwaltung

SwiftyEdit verfügt über eine effektive Rechteverwaltung für Besucher, Moderatoren und Administratoren.

Jeder Benutzer oder Administrator kann mit unterschiedlichen Benutzerrechten ausgestattet werden.
Die einzelnen Optionen findest Du unter <kbd>Benutzer</kbd> ▶ <kbd>Benutzer bearbeiten</kbd> ▶
<kbd>Passwort</kbd>, wo die Rechte-Checkboxen zusammen mit dem Passwort verwaltet werden.

## Zwei-Faktor-Anmeldung {#two-factor-authentication}

Mit der Zwei-Faktor-Anmeldung (2FA) braucht die Anmeldung im Backend neben dem Passwort einen
zweiten Faktor: einen Code per E-Mail oder aus einer Authenticator-App. Ein gestohlenes oder
erratenes Passwort allein reicht dann nicht mehr, um die Seite zu übernehmen.

2FA gilt nur für die Anmeldung im Backend (`/admin/`). Konten im Frontend (z. B. Kunden)
melden sich wie bisher an. Administratoren, die sich über das Frontend anmelden, bekommen dort
nur eine normale Benutzer-Session - Backend-Rechte gibt es ausschließlich über die
Backend-Anmeldung.

### 2FA einschalten {#2fa-enable}

2FA ist standardmäßig aus. Eingeschaltet wird sie für **alle** Backend-Zugänge gleichzeitig,
mit einer Zeile in `data/config.php` (siehe [Entwickler](09-00-developer.md)):

```php
<?php
// data/config.php
$se_2fa_required = true;
```

In den Einstellungen im Backend lässt sie sich bewusst nicht umschalten - eine gekaperte
Backend-Session soll den Schutz nicht abschalten können.

Sobald 2FA eingeschaltet ist, führt SwiftyEdit alle, die sie noch nicht eingerichtet haben,
bei der nächsten Anmeldung durch die Einrichtung. Backend-Nutzer können sie auch vorher schon
in ihren persönlichen Einstellungen einrichten (siehe unten), damit niemand von der Umstellung
überrascht wird. Solange 2FA aus ist, zeigt das Dashboard einen Hinweis, den Du ausblenden
kannst.

### Methoden {#2fa-methods}

Bei der Einrichtung wählt jeder eine von zwei Methoden:

* __Authenticator-App__ (empfohlen) - eine App auf dem Handy, z. B. Aegis, 2FAS, Google oder
  Microsoft Authenticator, zeigt alle 30 Sekunden einen neuen 6-stelligen Code. Zum Einrichten
  scannst Du den QR-Code oder tippst den Schlüssel darunter ein. Die App funktioniert offline
  und ist nicht auf E-Mails angewiesen. Der QR-Code entsteht im Browser, ein externer Dienst
  ist nicht beteiligt.
* __Code per E-Mail__ - bei jeder Anmeldung wird ein 6-stelliger Code verschickt. Er gilt
  10 Minuten und nur einmal. Diese Methode hängt am Mailversand - prüfe also, ob E-Mails von
  SwiftyEdit ankommen, bevor Du Dich darauf verlässt. Die Einrichtung ist erst abgeschlossen,
  wenn ein Code angekommen und eingegeben ist.

### Wiederherstellungscodes {#2fa-recovery-codes}

Am Ende der Einrichtung zeigt SwiftyEdit 10 Wiederherstellungscodes an (z. B. `4F7K-9QX2`).
Jeder davon ersetzt den Code aus der App oder der E-Mail **einmal** - für den Fall, dass das
Handy weg ist oder keine E-Mails ankommen. Die Codes werden nur dieses eine Mal angezeigt:
Drucke sie aus oder speichere sie in einem Passwortmanager. In den persönlichen Einstellungen
kannst Du neue Codes erzeugen, die alten gelten dann nicht mehr.

### Diesem Gerät vertrauen {#2fa-trusted-devices}

Nach der Eingabe des Codes kannst Du **Diesem Gerät 30 Tage vertrauen** anhaken. In diesem
Browser fragt die Anmeldung dann nur noch nach dem Passwort. Das Passwort ist immer nötig - ein
vertrautes Gerät überspringt nur den zweiten Faktor.

Vertraute Geräte stehen in den persönlichen Einstellungen und lassen sich dort entfernen. Sie
werden außerdem automatisch entfernt, wenn sich das Passwort ändert oder 2FA neu eingerichtet
wird.

### Persönliche Einstellungen {#2fa-personal-settings}

<kbd>Benutzermenü</kbd> (oben rechts) ▶ <kbd>Einstellungen</kbd>

Hier verwaltet jeder Backend-Nutzer seine eigene 2FA:

* einrichten (auch bevor 2FA für die Seite eingeschaltet ist),
* neu einrichten / Methode wechseln,
* neue Wiederherstellungscodes erzeugen,
* vertraute Geräte ansehen und entfernen,
* abschalten - nur möglich, solange 2FA in `data/config.php` nicht verlangt wird.

Änderungen verlangen das Passwort und einen aktuellen Code (oder einen
Wiederherstellungscode).

### Benutzerverwaltung {#2fa-user-management}

In der Benutzerliste zeigt ein Schild-Symbol, wer 2FA eingerichtet hat. Administratoren mit dem
Recht, Benutzer zu verwalten, können die 2FA eines anderen Benutzers auf der Bearbeiten-Seite
**zurücksetzen** - zum Beispiel, wenn jemand Handy und Wiederherstellungscodes verloren hat.
Bei der nächsten Anmeldung dieses Benutzers beginnt die Einrichtung dann von vorn. Die eigene
2FA lässt sich dort nicht zurücksetzen, dafür sind die persönlichen Einstellungen da.

### Notfälle {#2fa-emergencies}

| Situation | Lösung |
|---|---|
| Handy weg oder E-Mails kommen nicht an | mit einem Wiederherstellungscode anmelden |
| Handy und Wiederherstellungscodes weg, es gibt weitere Administratoren | ein anderer Administrator setzt Deine 2FA zurück |
| Du bist der einzige Administrator und hast keinerlei Zugang | Notschalter in `data/config.php` |

Der Notschalter überspringt 2FA für **einen** Benutzer bis zu einem bestimmten Zeitpunkt (in der
Zeitzone aus den Einstellungen der Seite):

```php
<?php
// data/config.php - Notfall: 2FA für diesen Benutzer bis zum angegebenen Zeitpunkt überspringen
$se_2fa_bypass = ['user' => 'admin', 'until' => '2026-12-31 12:00'];
```

Solange er gesetzt ist, zeigt das Dashboard eine Warnung. Öffne nach der Anmeldung die
persönlichen Einstellungen und wähle **Neu einrichten / Methode wechseln** - solange der
Notschalter für Dein Konto aktiv ist, reicht dafür Dein Passwort. Entferne die Zeile danach
sofort wieder.

### Gut zu wissen {#2fa-notes}

* Die Schlüssel der Authenticator-Apps werden verschlüsselt gespeichert. Der Schlüssel dafür
  stammt aus der Datei `data/site_secret.php`, die SwiftyEdit selbst anlegt. Halte sie geheim
  und nimm sie in Deine Sicherungen des `data`-Verzeichnisses auf - geht sie verloren,
  funktionieren die App-Einrichtungen nicht mehr und müssen neu eingerichtet werden (zum
  Anmelden einen Wiederherstellungscode oder den Notschalter verwenden).
* Änderungen an `data/config.php` können bis zu einer Minute brauchen, bis sie wirken, wenn der
  Server PHP-Dateien zwischenspeichert (OPcache).
* Falsche Codes sind begrenzt: Nach 5 falschen Codes beginnt die Anmeldung wieder beim Passwort.
